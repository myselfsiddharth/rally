# Rally Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Rally: personal agents that plan group parties (date, jobs, backups, calendar) and 1-on-1 meetups for a friend circle, with a tested engine, a seeded simulation, a replay web page, and a Discord + Google Calendar adapter.

**Architecture:** A pure TypeScript engine (`src/engine`) holds all decisions: time maths, the governor (caps and quiet hours), slot search, task assignment, pair matching, and event-sourced state machines for party and pair plans. A seeded simulator (`src/sim`) drives the same engine with fictional students. A Next.js app shows replays; adapters (`src/adapters`) connect Discord and Google Calendar and are tested with fakes.

**Tech Stack:** TypeScript (strict), Node 24, Next.js App Router, zod, vitest, fast-check for property tests. No other runtime dependencies in the engine.

**Spec:** `docs/superpowers/specs/2026-10-24-rally-design.md`

## Global Constraints

- Engine and simulator import nothing from `next`, Discord, Google, the network, `Date.now()` or `Math.random()`. Time and randomness come in as arguments.
- All times are UTC milliseconds (`Ms`); intervals are half-open `[start, end)`.
- Party cap: 1 party per friend circle per 14 days. Pair invites per person: max 2 per week, 1 per day. Pair cooldown after a decline: 7 days. Quiet hours default 22:00 to 08:00 local.
- Plan commits at readiness >= 0.8 and all critical tasks owned.
- Pair invites are double opt-in: person B is asked only after person A says yes.
- No private calendar label, dietary need or decline reason appears in any message sent to another agent or channel.
- Simulated output is always labelled `simulation`.
- Strict TypeScript, `zod` on every external input, tests with `vitest`. Commit after every task.

## Review Focus

1. **DST and time zones:** an evening window on a US daylight-saving change day (America/New_York, 2026-11-01) must still be 17:00 to 22:00 local. Test in Task 1.
2. **Duplicate and out-of-order messages:** delivering the same event twice, or an answer after a plan was cancelled, must change nothing and not throw. Test in Task 6.
3. **No overlap at all, everyone busy, or a circle of 1 or 2:** return an explicit "no slot" or "too small" result, never an empty plan or a crash. Test in Tasks 3 and 6.
4. **Nobody eligible for a task, or everyone declines it:** the plan ends in "needs host decision", not silence. Test in Task 4.
5. **The guest of honor:** never assigned a job for their own party, and for a surprise party their agent receives nothing. Test in Tasks 4 and 6.
6. **Messy calendars:** unsorted, overlapping, zero-length and midnight-spanning busy blocks must give correct free windows. Test in Task 1.
